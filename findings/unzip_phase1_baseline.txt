Verification:

  Pure-integer paths (Phases 1, 2a, 2b) are bit-exact (cmp byte-for-
  byte) vs the original FP code. Cross-path comparison gather FAST=OFF
  vs scatter FAST=OFF confirms unzip == unzip_scatter.

  SIMD paths (Phase 2d) are NOT bit-exact vs scalar (FMA fuses two
  rounds into one, reordering changes ULP results), but
    max abs diff:  2.78e-16  (machine epsilon)
    max rel diff:  2.94e-11
  vs the all-OFF baseline on the eO=6 d=8 grid. Analytic-field check
  isUnzipValid(..., 1e-3) passes for every measured config.

  (1) After always_inline, scatter_same_level_dispatch folds into the
      unzip_scatter symbol — the percentage moves but isn't a regression.

  After all optimizations:
  - Tensor wavelet kernels: 49% → 13% of runtime
  - std::__insertion_sort is mesh SETUP, not in the timed loop — discount
  - Remaining unzip_scatter body (~50% post-inline) is: per-(ele,blk)
    index math + the 7×7 = 49 row-copy memcpys per pair + cache-bound
    scatter writes into the unzip buffer

  Theoretical memory floor for this benchmark (~3.8 GB unzip writes
  over the 32-step loop at ~50 GB/s memory bandwidth single-core) is
  ~0.1 ms / dof=1 call. We're at 1.50 ms — there's still ~15× over the
  memory floor, mostly index arithmetic + cache misses on scattered
  writes. Further wins would need:
    - block-parallel processing across blocks (the hybrid OpenMP path)
    - tiling: process all elements feeding one block before moving on
      (the original gather variant at mesh.tcc:8970 has this shape
       but was abandoned in favor of unzip_scatter)
    - reducing getElementNodalValues cost (8.5% of runtime)


Notes:
  - SIMD code targets M ∈ {5, 7, 9}, covering eOrder ∈ {4, 6, 8}.
    Other M values fall back to scalar.
  - isUnzipValid fails at eO=2 on this mesh in ALL configs (pre-
    existing tolerance issue with the analytic field; not a regression).
  - All measurements sequential (no OpenMP, per MPI-first directive).
